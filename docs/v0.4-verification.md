# ShiftBridge v0.4 — trust and demo acceptance

Date: 2026-11-05 (Europe/Berlin). Target: the existing GitHub Pages project site; no NAS or AI API is connected.

## v0.4 change contract

1. Reject observation timestamps more than five minutes ahead of the browser clock. The small tolerance is for local clock skew, **not** evidence that a timestamp is genuine.
2. For a later observation on a *linked* issue, require its observation time to be strictly later than the latest existing confirmed observation in that issue's equipment scope. Reject an earlier/equal time instead of silently rewriting handover state. Original synthetic seed records remain historic sources.
3. When a question mixes SOP guidance with an issue-status request, return explicit abstention. A standalone maintenance question such as "What was checked for ISS-101?" retrieves maintenance sources rather than being mistaken for a SOP request.
4. Include a three-shift, single-issue synthetic case: `ISS-103`, `REC-104` OPEN, `REC-105` MONITORING, `REC-106` RESOLVED with recorded verification. Each stage must open its real source inspector and preserve the complete history.
5. Preserve ETCH-01 / ETCH-02 isolation, manual review and confirmation, version-aware SOP behaviour, localStorage compatibility and fail-closed storage warnings.

## Real-browser presentation checklist

Automated DOM testing (jsdom) checks behaviour, **not layout**. Human or actual-browser verification should explicitly record PASS/FAIL for:

- [ ] Desktop width near 1440 px: no clipped cards, source modal usable, guided entry obvious.
- [ ] Narrow mobile width near 390 px: navigation, three-shift story, form and citation buttons usable without horizontal clipping.
- [ ] Keyboard: navigation, input review, source dialog and return focus remain operable.
- [ ] Three-shift case: `REC-104` → `REC-105` → `REC-106`, with no implied equipment release.
- [ ] Guided demo: equipment → note → review/confirm → sourced handover → sourced Q&A.
- [ ] ETCH-02 switch excludes ETCH-01 history, sourced dialogs and cross-equipment answers.
- [ ] Archived pumpdown SOP cites old + successor without recommending obsolete operation.
- [ ] Reload retains local confirmed records; reset leaves seed records; blocked storage reports failed save.
- [ ] Public GitHub Pages asset check covers HTML, CSS, JS, JSON and version manifest.

Record actual device/browser results here only after execution; do not mark a checklist box as passed based only on source inspection or jsdom. The GitHub workflow checks public asset HTTP availability after publishing, not pixel layout.

## Honest limitations

Browser-local `localStorage` and client `Date.now()` are editable; neither is an authenticated audit trail or server-trusted clock. Linked temporal monotonicity is a demo conflict policy, not a complete late-entry/event-sourcing model. The parser supports limited deterministic note patterns; Q&A does not run an LLM. Synthetic verification text is self-declared; no external equipment telemetry or safety release is proven. For the actual UGREEN Skill / PDF scope and non-equivalences, see [UGREEN alignment review](ugreen-skill-proposal-alignment-v0.4.md).
